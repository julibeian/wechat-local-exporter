# 聊天媒体缺失修复验收（2026-10-09）

最新“家”群 HTML 归档包含 91 条消息，时间范围为 2026-10-03 至 2026-10-07。66 张图片和 11 个视频全部标为缺失，导出设置已经开启图片、视频和联网补全。

## 原因与修改

图片缓存实际存在。旧实现只保留数据库密钥，图片密钥每次都从当前微信登录进程读取。此次归档生成于 14:50:36，当前微信主进程启动于 14:51:38；旧实现可以从数据库缓存打开记录，却无法保证离线解密图片。用禁用实时密钥获取的回归测试复现了这一缺口。

现将图片密钥通过 Windows DPAPI 加密，单独保存在已有的账号缓存目录中。缓存绑定 Windows 用户、账号、账号路径与实际 wxid；复用前校验当前图片的加密数据。连接时尽量捕获有效图片密钥，导出时也可获取并保存；缓存损坏或失效后重新获取，不在设置文件或归档中写入密钥。短暂失败不会永久缓存为不可用。保留旧版 V1 图片解密支持。

视频的 XML 内容 MD5 与本机文件名不同。本机视频使用 `packed_info_data` 中的本地缓存标识，旧查找器没有保留这个字段，导致文件在本机但匹配失败。现同时保留内容 MD5 与本地 MD5，HTML 与 AI 资料包共用修复后的定位器；既有大小校验、账号目录限制和超限处理继续适用。

聊天原图无法读取、解密或解码时会尝试对应本机缩略图。HTML 保留缩略图标识并明确显示提示。自己的消息背景在浅色和深色主题中均为 `#95EC69`，文字为深色。GitHub 图标使用官方品牌包中的原始黑色 Invertocat SVG，深色主题显示白色；归档保持离线。

## 影响范围

| 导出方式 | 结论与验证 |
| --- | --- |
| HTML | 图片密钥与视频匹配两处均受影响；真实记录已重新导出并在 Edge 中验证 |
| PDF（包含图片） | 共用图片解析器，离线重开同样可能缺图片；真实样本恢复 66 张图片 |
| AI 完整资料包 | 共用图片解析器和视频定位器，两处均受影响；真实 ZIP 收录 66 张图片、11 个视频 |
| 朋友圈归档 / PDF | 共用本机图片解密器，已使用同一密钥缓存；新增离线缓存图片回归，既有朋友圈回归通过 |
| JSON、TXT、纯 JSONL | 按设计导出文字和元数据，不内嵌媒体；真实 JSON/TXT 均保持 91 条消息 |
| 批量聊天文件 | 使用独立附件解析器，不负责聊天图片或视频的归档 |

联网补全开关没有解决此次问题：聊天图片走本机解密、视频走本机定位，不能通过开启表情或封面下载来补齐这两个环节。

## 验收结果

- 新“家”群 HTML：91 条消息、66 张图片、11 个视频，77 个媒体全部收录，缺失为 0；其中 1 张使用明确标注的本机缩略图。
- 新旧归档的消息 ID 及顺序逐条相同；113 个归档文件的 SHA-256 校验通过。
- 禁用微信进程枚举并禁止媒体下载后，真实图片仍能解密，PDF 和 AI 资料包同样成功。未退出或重启用户的微信。
- Edge 通过本机 `file://` 打开真实归档：66 张图片全部解码、11 个视频逐个成功播放、官方 GitHub SVG 加载正常；浅色与深色主题的消息背景均为 `rgb(149, 236, 105)`。
- 390px 窄屏无水平溢出，页面无 JavaScript 错误。
- 统一构建运行全部回归测试，并执行成品离线自检和更新流程自检。新增成品自检直接验证 DPAPI 图片密钥复用与本地视频标识匹配，完全使用合成数据。
- 本机安装版与成品 EXE 的 SHA-256 相同，桌面快捷方式已更新；安装后独立离线自检通过，HTML 资源逐项与源码一致。
