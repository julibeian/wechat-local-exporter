## 实现

- 用 Flex 同行布局重建消息，使用 30px 圆头像、紧凑黑白气泡；时间脱离文档流，昵称悬停、键盘聚焦或点击时显示。
- 搜索、上下结果定位、筛选、日期、主题、打印和分块导航集中到左栏；窄屏折叠侧栏。
- 使用浏览器原生滚动、160 条 DOM 窗口、测量后的高度占位和锚点补偿。相邻窗口保留重叠节点，避免图片重复解码、动图重启。到达分块边缘后继续滚动或翻页键进入相邻分块；保留明确的手动入口。
- 从头像数据库按精确 username 读取并校验图片；支持同账号已有的本机解密头像缓存。新增头像库不会使旧版已验证的聊天缓存失效，核心库验证失败仍拒绝复用。
- 常见方括号表情转换成 Unicode 对应表情，保留源文本和替换位置。它们是语义对应的 Unicode 图形，并非微信原版贴图。未知方括号和 `[红包]` 等媒体标记不转换。
- 通话优先解析微信实际使用的 `diaplay_content` 字段（上游拼写如此），并支持其他可见状态字段。系统通知不再产生“未校准发送者”的头像和成员项。

## 明确限制

Browser 的 URL 策略拒绝直接访问私人归档的 file URL。交互和截图验收使用仅暴露独立合成样例的本机服务，真实记录仅在本机进行数据、图片和校验清单验证。

两份真实记录中仍有 10、33 条表情无法导出。检查了对应本机缓存、消息解密信息和表情数据库；现有解码方法没有还原这些加密表情，不能把它们当作已恢复。独立样例验证了可用 GIF 的加载及展示。HTML 保留不可用媒体提示。519 条归档还缺少 2 张本机不可用图片。

真实导出文件位于桌面的 `微信聊天导出_重做验收`，不纳入 Git。没有发布或上传。
