保持 Tkinter、Windows 本地读取、PyInstaller 单文件和 Inno Setup 架构。没有增加账号登录服务器、微信凭据保存或上传聊天数据的路径。未覆盖开发机已安装版本；正式发布状态及附件以 [v1.3.0 Release](https://github.com/julibeian/wechat-local-exporter/releases/tag/v1.3.0) 为准。

### 连接时序

用户点击连接 → 从运行中的 Weixin.exe 查找有效 `db_storage` → 唯一确认账号与 PID → 创建服务 → 限定该 PID 扫描并验证密钥 → 解密临时只读快照 → 再次确认账号 → 显示会话。

只有 `RestartRequired` 才进入主线程确认提示。确认后先验证连接组件和 DLL 缓存，再关闭/启动微信。捕获器不预先接收账号 A 的数据库；候选保留在内存，等待实际登录后的账号目录，再对该目录验证并创建服务。连接期间账号变化、路径歧义、微信退出都清理本次结果并停止。

### 更新时序

启动延迟 4 秒 → 独立后台线程检查公共 Release → 主界面显示状态/横幅。用户关闭横幅后保存 `dismissed_version`；同版本不再主动提醒，版本入口仍保留。手动检查可绕过自动检查周期。

用户下载 → 检查附件必须属于本仓库对应 Release、文件名/大小、HTTPS 和重定向主机 → 取已有 SHA256 清单 → `.part` 下载 → 校验 → 提示安装。下载不携带微信账号或路径；未验证的文件绝不执行。

用户确认安装且没有本地任务 → 创建本次独立安装子目录 → 复制 updater 与已验证包 → updater 再校验并打开父进程句柄 → 写 ready → 主程序清理数据库并退出 → updater 等待进程/文件占用结束 → 执行 Inno 或便携替换 → 启动新版。每次重试使用新的交接目录，避免慢启动的旧 updater 误用下一次确认。

安装版保留 Inno Setup 无管理员权限模式；便携版先在目标目录准备同卷临时文件，再原子替换。失败时保留原文件或尝试从 `previous.exe` 恢复并启动。成功事务可在后续启动清理，失败事务保留供恢复。

## 用户体验变化

- 启动不主动重启微信、不自动弹连接确认；账号初始显示“尚未确认当前登录账号”。
- 能直接连接时不打断微信；需要重新启动时才询问，并提醒保存未发送内容。微信负责登录，工具只确认本地账号。
- 标题旁可点击版本号；最新/新版/无法检查三种状态清晰，离线无更新错误弹窗。
- 可在程序内查看历史、下载和安装；安装前仍由用户确认，忙于连接/导出时延后。
- 连接区明显提醒常用电脑及本地历史范围；保留不上传、密钥仅内存、原数据库不修改的说明，同时如实说明更新和部分媒体会联网。

## 按需解密评估：本版不启用

可复用基础：`DecryptedWorkspace.prepare(relative_paths=...)` 已支持指定数据库；`load_metadata()` 和 `conversations()` 只需要 contact/session。新增合成数据库测试证明，没有 message/sns 时仍可显示会话。

但当前 `_message_databases()` 只列已解密且存在的文件。测试同样证明：直接延迟 message 解密却不改调用方，工作量统计会返回零，而不是“未准备”；这可能造成错误估时、漏导出。发送者校准在 Tk 调用链中读取消息库，直接在该处补解密又会卡住界面。朋友圈估时和导出也需要独立 sns 准备门控。

后续方案：为工作区引入每库状态（未准备/准备中/就绪/失败）、可取消的串行准备队列及只读快照锁；所有统计、校准、导出入口先 await/提交后台准备，再消费库。第一阶段只准备 contact/session；第二阶段首次聊天任务准备 message 分片、朋友圈任务准备 sns。还需要“会话→分片”索引策略：目前没有可靠映射，首次聊天任务可能仍需扫描所有消息库，不能声称已实现按会话精确解密。

进入下一版前应测试 WAL 一致性、并发估时/导出、失败重试、账号切换取消、关闭期间准备，以及真实大库首屏/首次导出耗时。本次没有读取用户的大型真实聊天库，也没有虚构速度提升倍数。v1.3 保留现有完整准备路径。

## v1.2 → v1.3 兼容性与边界

- 原 AppId、每用户安装目录、历史记录格式、导出目录及 TXT/PDF/朋友圈数据格式保持。首次从没有更新器的 v1.2 升级，必须手动运行一次 v1.3 安装包。
- Inno 从带版本名附件安装为稳定文件名，并清理旧版本 EXE。标准开始菜单/桌面快捷方式由安装程序更新；用户手建的快捷方式不保证自动修复。便携版原地升级保留原文件名。
- 同时运行多个账号或进程存在多个有效账号路径时，不猜测目标账号；请只保留目标账号。账号 UI 表示本次连接确认的快照，用户随后切换微信需重新连接本工具。
- 不保存数据库密钥、登录 token/cookie 或解密数据库缓存；非敏感本地路径/账号提示也不会附加到更新请求。
- 正常退出及可处理失败会清理临时数据库；强杀、断电、外部程序持续占用可能留下系统临时目录，不提供磁盘安全擦除或 Python 内存零化保证。
- SHA256 验证下载完整性，并依赖 HTTPS GitHub Release/校验清单的可信性；未加入商业代码签名、独立签名清单或反降级签名体系。网络封锁、代理证书问题只令更新不可用。
- 下载不覆盖旧程序。Inno 失败时尽力恢复旧 EXE，但不承诺回滚所有安装注册信息；中途断电/磁盘故障仍可能需要重跑安装包。已启动的新进程后续立即崩溃没有自动健康探测回滚。
- 更新源接口允许以后增加镜像，当前只配置 GitHub，不部署额外服务器。源码运行仅查看版本，不覆盖 Python。历史远程列表取最近 30 条正式/预发布记录中的正式版本，本地仍附带完整 RELEASE_NOTES。

## 发布前人工回归清单（未以合成测试代替）

1. 目标微信版本上，账号 A 已登录时直接连接成功；旧版本布局需要重启时出现确认，拒绝不关闭微信。
