# 微信已登录时启动耗时修复

2026-10-10，本机 v1.6.1 修复，未发布到 GitHub。

用户反馈卡在“正在同步数据库或读取会话列表”。实测发现数据库缓存已经复用，主要等待发生在同步前后的账号确认。原连接会扫描全部 5 个 Weixin.exe 进程的内存，并在同步完成后再次扫描主进程。同步完成后的最后一次扫描期间，界面仍可能显示同步或读取列表的进度文字。

## 根因和修复

原安装版连接流程重新实测共 33.339 秒，其中 6 次全内存扫描占 31.050 秒；数据库准备仅 0.458 秒。上次只验证了数据库缓存复用，遗漏了微信已经运行时的完整账号确认流程。

同账号快速路径现同时验证：Windows 查询返回的数据库使用进程、该进程的创建时间，以及 Weixin.dll 中的当前登录账号。保存的目录只能作为待核验线索。多个客户端、未知登录身份、权限失败、PID 复用或目录变化均回退到原完整发现流程。数据库密钥验证、每个数据库及 WAL 的变化检查、变化后的重新解密都保留。连接结束后重新检查当前账号，切换账号时丢弃本次工作区。

系统资源使用查询仅调用 Restart Manager 的 StartSession、RegisterResources、GetList、EndSession；不调用关闭或重启进程接口。接口依据 [Microsoft 的 RmGetList 文档](https://learn.microsoft.com/en-us/windows/win32/api/restartmanager/nf-restartmanager-rmgetlist) 和 [Restart Manager 函数列表](https://learn.microsoft.com/en-us/windows/win32/rstmgr/functions)。无需新增依赖。

完整扫描回退也做了加速：先查找 db_storage 标记，只在附近的有限范围解析路径；继续支持大小写、UTF-8、两种 UTF-16 对齐和多个账号，避免相邻盘符被拼进同一个路径。

| 该 GUI 轮次连接及读取列表 | 2.102 秒 | 自动检测并连接；关闭可选的联网更新检查以测量本地流程 |
| 更新后安装 EXE 冷启动 | 第 8.080 秒观察到列表已完成 | 第 6.049 秒显示索引已就绪，第 8.080 秒显示已读取 199 个会话；包含安装版自解压和加载 |
| 3 个聊天数据库全部重新同步 | 0.417 秒 | 合计 169,996,288 字节；在隔离副本中修改源文件时间触发完整刷新 |
| 同样 3 个聊天数据库无变化 | 0.023 秒 | 全部复用，逐个校验 SQLite 可读 |

以上是本机测量，不是其他电脑或首次连接的时间保证。连接流程时间不等同于双击安装版到完整窗口出现的时间；GUI 测量包括源码导入、窗口创建、自动检测、连接和列表绘制，不含安装版自解压启动。没有重启微信或修改真实微信数据库。数据库刷新测量使用真实加密数据库的一致副本，强制刷新后核对解密内容完全一致；它是刷新成本测量，不代表在真实微信里发送了新消息。

安装版冷启动使用实际安装 EXE 新建进程，间隔两秒检查其自身窗口；8.080 秒是首次观察到完成的时间上界，不是精确完成时间。状态截图仅保留本软件标题和底部进度，排除联系人和聊天内容。测量后软件保持打开。

原安装版基线通过提取当时安装 EXE 的 connection/windows 代码测量，并沿用未在本次修改的缓存准备流程。收据保存在忽略目录 outputs/startup-latency-fix-20261010：startup-baseline-installed.json、startup-after.json、startup-fast.json、gui-startup.json、database-refresh.json。startup-before.json 是中途仅优化路径解析的 19.429 秒记录，不作为原版本基线。

## 验收

- 覆盖账号切换、多个登录、身份未知、无法枚举客户端、数据库不再由微信使用、PID 复用及目录缺失等回退情况。
- 回归确保校验通过的重新打开和连接末尾核验均不触发全内存扫描；数据库缓存验证与变化刷新仍执行。
- Windows 本机测试及成品离线自检均检查系统查询能识别当前进程实际打开的合成文件及创建时间。
- 构建后核对安装 EXE 的模块与当前源码、HTML 资源一致，并核对桌面快捷方式的目标。
